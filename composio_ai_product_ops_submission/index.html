100-App Integration Intelligence

Headline: the API existing is not the same as an integration being buildable. The strongest opportunities combine self-serve credentials + broad API surface + predictable permissions; the hardest cases are gated by enterprise access, approvals, licensing or immature developer surfaces.

Snapshot date: 17 Aug 2026. The final human verification loop is deliberately marked pending rather than claiming fabricated accuracy.

Executive findings

01 — Access is the bottleneck. A documented API can still be commercially or administratively gated.
02 — OAuth is the dominant public-integration pattern. Private/internal use often uses API keys or tokens.
03 — REST remains the broadest common surface. GraphQL is a strong secondary pattern in modern SaaS.
04 — MCP is an acceleration signal. Existing MCP implementations reduce tool-design effort, but official and community MCP must be separated.
05 — Developer-first products are the easy wins. Mature APIs plus self-serve credentials shorten toolkit time-to-value.
06 — Gated apps belong in outreach, not automatic rejection. Broad API + access gate is a partnership problem.

Opportunity matrix

🟢 Easy wins
Self-serve + broad API. Build first and reuse auth patterns.
🟢 Constrained wins
Broad API with admin, plan or review friction.
🟡 Outreach
Broad API but enterprise/contact/approval gate.
🔴 Validate / deprioritize
Narrow, unstable or non-general-purpose API.

Research agent

1. Discover
Official developer, auth, API, access and MCP sources.
2. Extract
Strict structured fields; no unrestricted prose.
3. Challenge
API existence ≠ credential access; community MCP ≠ official MCP.
4. Verify
Stratified sample + claim-level source checking.
5. Prioritize
Build, constrain, outreach or deprioritize.

The repo contains the runnable research-agent scaffold and verification sampler. A live search/browser provider should be connected before claiming a completed live run.

Sample across all 10 categories and deliberately include gated products, unusual auth, low-confidence records and MCP claims.

Scoring

Mark each claim SUPPORTED / CONTRADICTED / UNRESOLVED. Accuracy = supported ÷ (supported + contradicted).
